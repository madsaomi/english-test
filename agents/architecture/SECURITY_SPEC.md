# 🔐 Спецификация безопасности и защиты от списывания (SECURITY_SPEC.md)

Этот документ описывает механизмы защиты API, данных пользователей и предотвращения читерства.

---

## 1. Защита от списывания (Anti-Cheat)

### Разделение моделей `Question` и `ClientQuestion`:
- В наборе тестов (`tests_data/test_general_2026.json`) хранится полная модель `Question`:
  - `correct_option: int`
  - `explanation: str`
- При выдаче вопроса клиенту через API (`cat_engine.to_client_question`) создается урезанная модель `ClientQuestion`:
  - Поля `correct_option` и `explanation` **ФИЗИЧЕСКИ ОТСУТСТВУЮТ** в JSON-ответе.
  - Попытка открыть DevTools (`F12`), вкладку `Network` или глобальные JS переменные не дает пользователю возможности узнать правильный ответ заранее.

### Валидация времени ответа:
- Клиент передает параметр `time_spent_seconds`.
- Если ответ пришел быстрее 0.5 секунды (подозрение на бота или случайный автокликер), время нормализуется до минимально допустимого.

---

## 2. Безопасность Telegram-токена

- Токен бота `BOT_TOKEN` **никогда** не передается во фронтенд и не фигурирует в ответах API.
- Запросы к Telegram Bot API отправляются исключительно сервером в фоновом режиме.

---

## 3. CORS и сетевая безопасность

- В `backend/main.py` настроен CORS middleware:
  - В среде разработки разрешены все origins для удобства тестирования локально и через туннели (`localtunnel`, `ngrok`).
  - Для продакшна в строгих корпоративных сетях `allow_origins` может быть ограничен доменным именем сервиса.
