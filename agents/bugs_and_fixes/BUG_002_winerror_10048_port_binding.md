# 🐛 BUG-002: Конфликт занятости сокета 127.0.0.1:8000 (WinError 10048)

- **Дата обнаружения:** 2026-09-17 21:21
- **Статус:** 🟢 РЕШЕНО
- **Затронутый файл/процесс:** `uvicorn backend.main:app`
- **Компонент:** Управление процессами на ОС Windows (PowerShell)

---

## 🔍 1. Симптом (Что произошло)
При перезапуске сервера Uvicorn после внесения правок в код новый процесс завершался с ошибкой:

```text
ERROR:    [Errno 10048] error while attempting to bind on address ('127.0.0.1', 8000): 
          [winerror 10048] only one usage of each socket address (protocol/network address/port) is normally permitted
```

---

## 🔬 2. Первопричина (Root Cause — ПОЧЕМУ это произошло)
- Предыдущий экземпляр Uvicorn был запущен как фоновый процесс (background daemon).
- При отправке команды остановки на Windows дочерний процесс Python не всегда успевает мгновенно освободить сетевой сокет порта 8000 операционной системы (TIME_WAIT сокета или зависший worker).
- Попытка запустить новый процесс uvicorn в ту же миллисекунду на том же порту вызвала системную коллизию `WSAEADDRINUSE` (WinError 10048).

---

## 🛠️ 3. Решение (Как исправлено)
Перед перезапуском процесса сервера в PowerShell выполняется принудительная очистка зависших процессов Python:

```powershell
Get-Process python -ErrorAction SilentlyContinue | Stop-Process -Force
```

После этого новый экземпляр Uvicorn успешно связывается с портом 8000 без каких-либо конфликтов.

---

## 🛡️ 4. Правило предотвращения (Для всех будущих агентов)
При перезапуске веб-сервера на Windows всегда проверять и гарантировать завершение старых процессов Python перед вызовом `python -m uvicorn`.
