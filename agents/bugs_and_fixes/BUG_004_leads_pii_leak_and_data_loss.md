# BUG_004: Лиды терялись при каждом деплое + экспорт лидов без авторизации

**Дата обнаружения:** 2026-09-26
**Обнаружено:** полный аудит проекта (PLAN-015)
**Severity:** 🔴 HIGH (потеря персональных данных + публичная утечка PII)
**Статус:** ✅ ИСПРАВЛЕНО (PLAN-015)

---

## 1. Симптом

1. `GET /api/export/leads` возвращал **все** лиды (ФИО, телефон, `@username`, уровень, результат) **без какой-либо аутентификации** — любой, кто знал URL, получал персональные данные клиентов.
2. `backend/lead_store.py` писал лиды в `data/leads.json` и в докстриме заявлял персистентность, но:
   - `.dockerignore` содержит `data/` → в Docker-образ файл **не попадает**;
   - Railway **не монтировал том** в `/app/data`;
   - итог: при каждом рестарте/рестарте-по-ON_FAILURE/новом деплое файловая система контейнера пересоздавалась, и **все заявки терялись**.

## 2. Первопричина (Root Cause)

| # | Причина |
|---|---|
| 1 | Эндпоинт экспорта спроектирован как «внутренний», но был смонтирован на том же публичном FastAPI без auth-зависимости. `main.py` не содержал ни одного `Depends()` для защиты. |
| 2 | Путь к данным был **захардкожен** в `lead_store.py` (`Path(__file__).parent.parent / "data"`) и не вынесен в конфиг, поэтому его нельзя было перенаправить на внешний том. |
| 3 | Отсутствовали security-чеки в `check_integrity.py`, поэтому дыра не была поймана автопроверками. |
| 4 | В `.env.example` не было переменных для ключа и пути данных — нечего было настроить. |

## 3. Решение (How Fixed)

| Файл | Изменение |
|---|---|
| `backend/config.py` | Добавлены `EXPORT_API_KEY` и `DATA_DIR` (оба из env, `DATA_DIR` по умолчанию `<repo>/data`) |
| `backend/main.py` | `export_leads(x_api_key: Optional[str] = Header(alias="X-API-Key"))`: если `EXPORT_API_KEY` не задан → **503** (эндпоинт отключён); если заголовок отсутствует/неверен → **401**; сравнение через `hmac.compare_digest` (защита от тайминг-атак) |
| `backend/lead_store.py` | `DATA_DIR` теперь импортируется из `config` — путь переопределяется переменной окружения |
| `railway.json` | Добавлен volume `lead-data` с `mountPath: /app/data` |
| `.env.example` | Документированы `EXPORT_API_KEY` (с генерацией) и `DATA_DIR=/app/data` |
| `agents/tools/export_results.py` | Читает `EXPORT_API_KEY` из env/`.env` и отправляет заголовок `X-API-Key`; предупреждает, если ключ не задан |
| `agents/testing/test_api_http.py` | `TEST_EXPORT_KEY` через `os.environ` **до** импорта `backend`; новый тест `test_export_leads_requires_api_key` (401 / 401 / 200) |
| `agents/tools/check_integrity.py` | Новый **раздел 6 «Проверка безопасности и персистентности»** — 7 проверок |

## 4. Правила предотвращения

1. **Любой эндпоинт, отдающий PII (ФИО/телефон/@username), обязан иметь auth-проверку** и тест на 401.
2. **Auth-зависимости — только через `Header`/`Depends` в `main.py`**, никаких «защищённых» эндпоинтов без проверки.
3. **Любой путь для записи данных — только через `config.py`**, иначе его нельзя перенаправить на том.
4. **Любая персистентность в контейнере требует volume** и проверки в `check_integrity.py` (раздел 6).
5. **Новые env-переменные обязаны быть в `.env.example`** и покрыты integrity-чеком.
6. Пустое/отсутствующее значение секрета в проде → **fail-closed** (503), а не fail-open (200).

## 5. Обязательные ручные шаги в Railway (после деплоя)

1. Variables: `EXPORT_API_KEY=<python -c "import secrets; print(secrets.token_urlsafe(32))">`
2. Variables: `DATA_DIR=/app/data`
3. Volume `lead-data` → mount path `/app/data` (уже описан в `railway.json`, но том создаётся в UI)
4. Старую копию лидов (если сохранилась локально) перенести в том вручную
5. Проверка: `curl -H "X-API-Key: <ключ>" https://<domain>/api/export/leads` → 200; без заголовка → 401
