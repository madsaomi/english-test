# 🏛️ ADR-001: Единый процесс FastAPI + aiogram вместо микросервисов

- **ID решения:** ADR-001
- **Статус:** 🟢 ACCEPTED (Принято)
- **Дата:** 2026-09-17
- **Контекст:** Пользователь запросил: *«и сервер тоже было 1 на оба и на телеграм и на сайт»*.

---

## 1. Контекст и проблема
Требовалось создать платформу с веб-сайтом тестирования и Telegram-ботом, работающую на едином сервере без усложнения инфраструктуры (без оркестрации множества отдельных контейнеров, очередей сообщений RabbitMQ/Redis и сложного мониторинга).

---

## 2. Рассмотренные альтернативы
1. **Альтернатива 1: Два отдельных микросервиса (Web-сервер + Отдельный Bot Worker)**
   - *Плюсы:* Изоляция сбоев (если упадет бот, сайт продолжит работать).
   - *Минусы:* Требует общей базы данных или брокера сообщений для связи, удваивает потребление памяти, усложняет деплой и конфигурацию для пользователя.
2. **Альтернатива 2: Единый асинхронный процесс (FastAPI + aiogram lifespan)**
   - *Плюсы:* Один порт, один процесс Python, общий Event Loop, мгновенный доступ из веб-обработчиков к функциям отправки Telegram-сообщений, нулевые накладные расходы на IPC (inter-process communication).
   - *Минусы:* Нельзя блокировать Event Loop синхронным кодом.

---

## 3. Принятое решение
Принят **Вариант 2 (Единый процесс)**.  
Бот запускается в фоновом таске внутри FastAPI `lifespan`:
```python
bot_task = asyncio.create_task(dp.start_polling(bot))
```
Если бот не настроен, сайт работает в отказоустойчивом Демо-режиме.

---

## 4. Последствия
- Сервер разворачивается одной командой: `python -m uvicorn backend.main:app`.
- Отправка контактов из веба в Telegram происходит мгновенно в памяти через вызов корутины `send_result_notifications()`.
- Строго запрещены синхронные блокирующие вызовы (зафиксировано в `ANTI_PATTERNS.md`).
