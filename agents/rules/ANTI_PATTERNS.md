# 🚫 Свод Анти-Паттернов (Чего делать КАТЕГОРИЧЕСКИ нельзя)

> [!CAUTION]
> Любой агент, нарушивший правила из этого файла, ставит под угрозу работоспособность всей платформы и безопасность пользователей.

---

### 1. ❌ Передача правильных ответов во фронтенд (Security / Anti-Cheat)
- **ЗАПРЕЩЕНО:** Передавать в `ClientQuestion` поле `correct_option` или `explanation` до завершения ответа.
- **ПОЧЕМУ:** Любой школьник может нажать `F12` (DevTools) ➔ `Network` / `Console` и мгновенно увидеть правильные варианты.
- **КАК ПРАВИЛЬНО:** На клиент отдавать только `ClientQuestion` без ответов. Валидация происходит **исключительно на бэкенде** в `cat_engine.py`.

---

### 2. ❌ Синхронные блокирующие вызовы в асинхронном коде (Performance)
- **ЗАПРЕЩЕНО:** Использовать `time.sleep()`, `requests.get()`, `urllib.request.urlopen()` внутри эндпоинтов FastAPI или хэндлеров aiogram.
- **ПОЧЕМУ:** Сервер работает в едином Event Loop на одном потоке. Блокирующий вызов `time.sleep(5)` заморозит сервер **для абсолютно всех пользователей сайта и бота на 5 секунд**.
- **КАК ПРАВИЛЬНО:** Всегда использовать `asyncio.sleep()` и `aiohttp.ClientSession()`.

---

### 3. ❌ Перезапись или удаление файлов журнала сессий (Memory Integrity)
- **ЗАПРЕЩЕНО:** Перезаписывать старые файлы в `agents/history/` или удалять их.
- **ПОЧЕМУ:** Теряется непрерывный аудит, контекст и причинно-следственная связь разработки.
- **КАК ПРАВИЛЬНО:** Каждая сессия создает новый инкрементальный файл с уникальной меткой времени и порядковым номером.

---

### 4. ❌ Хранение секретов и токенов в кодовой базе (Hardcoded Credentials)
- **ЗАПРЕЩЕНО:** Вставлять реальные токены Telegram-бота (`123456:ABC...`) или ключи API прямо в файлы `.py` или `.js`.
- **ПОЧЕМУ:** При публикации кода на GitHub или передаче третьим лицам бот будет скомпрометирован.
- **КАК ПРАВИЛЬНО:** Только через `.env` и файл `backend/config.py`.

---

### 5. ❌ Необработанные поля None в Pydantic v2 моделях
- **ЗАПРЕЩЕНО:** Писать `field: Model = None` без `Optional`.
- **ПОЧЕМУ:** В Pydantic v2 это порождает критическую ошибку валидации `ValidationError: Input should be a valid dictionary or instance of Model`.
- **КАК ПРАВИЛЬНО:** Всегда `Optional[Model] = None` или `Model | None = None`.

---

### 6. ❌ Прямое изменение состояния сессии в обход CATEngine
- **ЗАПРЕЩЕНО:** Менять `session.ability` напрямую из эндпоинтов FastAPI.
- **ПОЧЕМУ:** Ломается баланс адаптивности, история стрейков и статистика навыков.
- **КАК ПРАВИЛЬНО:** Вызывать исключительно методы `cat_engine.submit_answer()` и `cat_engine.finalize_test()`.

---

### 7. ❌ Написание или изменение кода без предварительно утвержденного плана (Unplanned / Cowboy Coding)
- **ЗАПРЕЩЕНО:** Писать, редактировать или удалять файлы кода, ставить зависимости или запускать модифицирующие команды без составленного и **утвержденного пользователем** плана (`implementation_plan.md` / `agents/plans/`).
- **ПОЧЕМУ:** Кодинг «на лету» без плана ломает архитектуру, порождает скрытые регрессии, ломает рабочий функционал и заставляет пользователя перезапускать сессию и повторять всё заново.
- **КАК ПРАВИЛЬНО:**
  1. Сначала исследовать код.
  2. Написать полный план решения с файлами и верификацией.
  3. **Дождаться подтверждения пользователя (Proceed / согласие в чате).**
  4. И только после явного одобрения приступать к написанию кода.
